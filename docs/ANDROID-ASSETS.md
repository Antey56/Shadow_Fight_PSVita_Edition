# Android assets: read-only backend

Реализован файловый backend для 11 функций AAsset: открытие, чтение, seek, длина, остаток, получение буфера и закрытие. Контракты основаны на [Android NDK asset API](https://developer.android.com/ndk/reference/group/asset). Это кандидат для будущей интеграции, а не подтверждение запуска Unity.

Менеджер получает путь к доверенному, заранее распакованному каталогу assets. Каждый handle имеет независимую позицию. Открытие не загружает файл целиком; getBuffer выделяет память только по запросу и в пределах заданного лимита на файл. Нулевой лимит отключает буфер, максимальный — 64 MiB. Это не общий лимит всех открытых handles: общий бюджет должен контролировать вызывающий код.

Имена проверяются на абсолютные пути, пустые компоненты, точку, две точки, обратные слеши, двоеточия и управляющие символы. Проверка лексическая: каталог должен быть неизменяемым и доверенным, без symlink/reparse подмен. Это не файловая песочница. Нельзя одновременно читать и закрывать один handle из разных потоков.

Начальная реализация принимает обычные файлы размером до INT32_MAX, включая для 64-битных функций. Seek допускается от начала до конца файла. Ошибки чтения возвращают отрицательный результат, EOF — ноль; ошибки открытия/буфера — NULL, seek — минус один. Режимы открытия являются подсказками; отдельной оптимизации для них пока нет. Буфер живёт до закрытия handle.

Сигнатуры используют явные Android ARMv7 32/64-битные ширины и базовый AAPCS для ARM GCC. Каталог адресов разрешён только при сборке Vita ARM32. Host DLL предназначена для проверки нашего кода; её адреса нельзя передавать гостевому ARM ELF. Согласование ABI всего runtime и аппаратные проверки ещё необходимы.

Не реализованы чтение ZIP напрямую, AAssetManager_fromJava, перечисление каталогов, файловые дескрипторы Android, запись и сохранения. Без Java/JNI bridge нельзя считать наш manager заменой объекта, полученного от Android Activity. Статические совпадения импортов перечислены в asset-adapter-status.json; динамический lookup этим не доказывается. Счётчик 451 нерешённых обязательных импортов не уменьшен.

## Проверка

77 Python/integration tests и 5 CTest targets проходят локально; Vita cross-build проходит. 16 новых тестов проверяют чтение, seek/overflow, независимость handles, лимиты буфера, некорректные пути и ошибки. Аппаратной проверки нет.

Четыре файла оригинального APK (10 199 148 байт) прочитаны нашим C backend: SHA-256 потока и буфера совпали с ZIP, проверены чтения после seek и сохранение позиции. Временные образцы удалены. Публикуется только отчёт с путями, размерами, хешами и результатами; игровые данные не включены.

```sh
python tools/verify_asset_backend.py /path/to/game.apk --host-library build-host/android_asset_host.so --out reports/my-asset-verification.json
```

На Windows использовать build-host/android_asset_host.dll. Сначала выполнить host build из README. Следующий интеграционный этап — установить реальный путь доступа Unity к данным, затем реализовать нужную часть JNI/lifecycle. Android-код и Unity на этом этапе не исполнялись.
